# 《星尘消除》实现说明（game/）

对应实验一《01_需求分析文档》的实现阶段。**纯 HTML5 + 原生 ES 模块，零依赖、零构建**（满足 NFR-01e 资源轻量、NFR-02c 无插件依赖）。

## 目录结构

```
game/
├── index.html            # 入口页面（浏览器直接打开即可游玩）
├── src/
│   ├── config.js         # 全局常量：计分/星级/经济/动画时长（唯一权威定义）
│   ├── score.js          # 计分与星级（FR-06 / FR-07）
│   ├── levels.js         # 30 关配置（FR-08，数据驱动）+ 配置校验（FR-05 异常处理）
│   ├── board.js          # 核心玩法引擎：棋盘/交换/消除/连锁/特殊方块/死局洗牌（FR-01~FR-06）
│   ├── storage.js        # 存档：损坏备份、版本迁移、写入失败、降级（FR-11、7.2）
│   ├── audio.js          # 音效（Web Audio 合成 + 不可用时静默降级，FR-15）
│   ├── ui.js             # 界面与渲染（Canvas 2D 棋盘 + DOM 面板，FR-12/FR-16）
│   └── main.js           # 游戏状态机与页面导航
└── tests/
    ├── logic.test.mjs        # 自动化验证（63 项断言，覆盖 AC-01~AC-07/AC-11/AC-13/AC-14/AC-21~24 等）
    ├── sim-player.mjs        # 模拟玩家（贪心 / 休闲），供可通关性与难度验证使用
    ├── calibrate-levels.mjs  # 关卡目标值与难度校准（AC-11 依据，可复跑）
    └── smoke.mjs             # 性能烟测（棋盘生成、交换结算耗时）
```

## 运行方式

- **玩游戏**：双击 `game/index.html`（或任意静态服务器打开）——无需安装任何依赖。
- **跑测试**：`cd game && node tests/logic.test.mjs`（Node ≥ 18）
- **重跑难度校准**：`node tests/calibrate-levels.mjs`

## 核心实现要点（与需求文档的对应）

| 需求 | 实现位置与要点 |
| --- | --- |
| FR-01 初始化 | `createBoard`：拒绝采样保证**无初始 3 连**；再校验**至少 1 个合法交换**，50 次内未满足则洗牌修正 |
| FR-02 交换判定 | `resolveSwap`：无效交换弹回且**逐格状态完全还原**（AC-04 已验证 1641 次无效交换） |
| FR-03 连锁与死局 | 消除→下落→补充循环；「无连线且无待处理效果」时检测死局并**自动洗牌（不消耗步数）** |
| FR-04 特殊方块 | 4 连→条纹、L/T→炸弹、5 连→彩虹；双特殊交换→十字组合爆发（按 2 次连锁计分） |
| FR-05 目标与步数 | 两类目标（`score` / `clear`），达成即结算；锤子消除计入消除目标但不计分 |
| FR-06 计分 | 逐次连锁计分 = 消除数 × 20 × min(1+0.5(n-1), 2.5)；测试可逐项复算 |
| FR-07 星级 | R = 结算总分 / scoreTarget，≥1.0/1.3/1.6 → 1/2/3 星 |
| FR-11 存档 | 单键 `stardust_save`，写临时键后覆盖（原子性）；损坏→备份到 `stardust_save_corrupt_<ts>` 并重置；配额耗尽→返回失败由 UI 提示；无痕/禁用→内存降级 |

## 关卡难度校准（AC-11 证据）

`tests/calibrate-levels.mjs` 用**模拟玩家**实测校准每关的星级基准分：

- 1 星线由**不动点迭代**求得：反复令 `scoreTarget ← quantile_q(以当前 scoreTarget 为停止条件的结算总分)`；收敛后 q 即模拟玩家的失败率。三章分别取 q = 10% / 20% / 30%（逐章变难）。
- 消除型关卡使用"目标色优先"策略建模，目标值 `objectiveTarget` = 目标色消除量的 P20。
- 步数奖励 `bonusPerStep = 0.8 × scoreTarget / moves`，使 **2 星 ≈ 剩余 37% 步数、3 星 ≈ 剩余 75% 步数**。

最近一次校准与验证结果（种子固定，可复现）：

| 指标 | 结果 |
| --- | --- |
| 贪心玩家通关率 | ≈ 82%（30 关每关至少通关 1 次，全部关卡可通关） |
| 休闲玩家（随机合法走法）通关率 | ≈ 44% |
| 贪心玩家星级分布 | 1 星 85 / 2 星 76 / 3 星 36（通关局中 3 星占 18%） |

## 实现阶段发现并修订的数值问题（详见《02_AI协作记录》M-14）

1. **固定"剩余步数 200 分/步"与星级阈值不匹配**：在"达成即结算"规则下，结算总分 ≈ 目标分 + 200×剩余步数，导致 3 星（需 1.6 倍目标分）几乎不可达。→ 改为步数奖励与目标分挂钩（`BONUS_RATIO = 0.8`），并回写《01》FR-06-4/FR-07。
2. **消除型关卡 `targetColor` 为负**：JS 负数取模（`(-5) % 6 === -5`）使第 3 章前 5 关永远清不到目标色；已在 `levels.js` 归一化，并给 `validateLevel` 增加非负校验（测试保留回归用例）。
3. **3 色棋盘洗牌后残留连线**：纯随机重排无法同时满足"无连线 + 可玩"，改为**构造式排布**（逐格挑选不成 3 连的颜色），并把死局处理移入连锁循环，使洗牌引入的连线也会被继续结算。
