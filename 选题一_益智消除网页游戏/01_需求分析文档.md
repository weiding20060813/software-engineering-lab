## 2. 背景与问题陈述

### 2.1 背景

三消（Match-3）是全球移动休闲游戏最成熟的品类之一。从 Candy Crush Saga 到国内的开心消消乐，再到 2022 年现象级产品《羊了个羊》，反复验证了该玩法广泛的用户基础与极强的碎片时间适配性（来源：SRC-B）。同时，HTML5 技术（Canvas 2D 渲染、Web Audio API 音效、localStorage 本地存储）已足以支撑轻量级网页游戏，无需安装、打开即玩（来源：SRC-C）。

### 2.2 问题陈述

对目标用户（学生与年轻上班族）而言，现有主流消除游戏普遍存在以下痛点：

1. **强制联网与账号绑定**：多数产品要求账号登录，在断网环境（地铁、飞行模式、校园弱网）下不可用；
2. **广告打断心流**：过关失败或间隔期强制播放广告，《羊了个羊》还因"几乎不可通关 + 广告复活"引发大面积舆论批评（来源：SRC-B，待人工复核）；
3. **体力值限制**：连续游玩被体力系统截断，与休闲玩家"想玩就玩"的预期冲突；
4. **内购驱动数值**：后期关卡难度曲线被付费道具设计扭曲，零氪体验差；
5. **功能臃肿**：社交、公会、活动、赛季等模块堆叠，偏离"轻量休闲"定位。

### 2.3 项目定位与目标

本项目定位为**轻量级、纯单机、无打扰的网页消除游戏**：以关卡制三消为核心，通过本地存档保证进度连续，通过积分、星级与本地排行榜提供成就反馈，通过音效与动画提供操作爽感；**不做**账号、联网、广告、内购与体力系统。

产品目标（成功标准，详见第 8 章验收标准）：

1. 玩家在完全离线环境下可持续游玩全部 30 关；
2. 中端手机上动画流畅（≥50 fps），操作反馈及时（≤100 ms）；
3. 无任何打扰性机制（无广告、无体力、无强制登录）；
4. 关卡配置数据驱动，新增关卡不改代码。

## 5. 功能需求详述

> 每条需求含：描述、输入/输出与数据、业务规则、异常处理、验收要点（AC）、优先级、来源。

### 5.1 核心玩法

#### FR-01 棋盘与方块初始化（高，SRC-A/SRC-D）

- **描述**：游戏必须提供由彩色方块构成的矩形棋盘。默认 8×8；关卡配置可指定 7×7 至 9×9（见 7.1）。方块颜色种数由关卡配置指定（4–6 种）。
- **规则**：
  1. 初始棋盘必须不含任何 3 连及以上连线；
  2. 初始棋盘必须保证至少存在 1 个合法交换（即交换后能形成消除），杜绝"开局死局"；
  3. 补充方块从该关颜色池中等概率随机生成。
- **异常处理**：若初始化时随机生成 50 次仍未满足规则 1、2，必须重新生成直至满足（不阻塞游戏）。
- **验收要点**：AC-01、AC-02。

#### FR-02 交换操作与消除判定（高，SRC-A/SRC-D）

- **描述**：玩家必须能通过以下任一方式交换相邻方块：① 点击/点触选中后点击相邻格；② 鼠标/手指按住并拖拽至相邻格；③ 键盘方向键 + 确认键（桌面，见 FR-18）。
- **规则**：
  1. 交换后若在交换位置形成 3 个及以上同色横/竖连线，判定为**有效交换**：该连线内全部方块消除，消耗 1 步；
  2. 若未形成连线，判定为**无效交换**：双方块在 300 ms 内弹回原位，不消耗步数；
  3. 每次交换必须在上一轮消除动画完全结束后才可发起（防止并发状态错误）。
- **异常处理**：动画播放中输入锁忽略（防连点造成状态错乱）。
- **验收要点**：AC-03、AC-04。

#### FR-03 连锁、下落补充与死局处理（高，SRC-A/SRC-D）

- **描述**：消除后必须执行"下落—补充—再判定"循环，形成连锁。
- **规则**：
  1. 消除后，上方方块必须下落填补空缺，顶部补充新方块；下落与补充动画总时长 ≤300 ms；
  2. 补充后若出现新连线，必须自动继续消除（连锁 +1），重复直至无新连线；连锁次数无上限，动画串行执行；
  3. 连锁结束后若棋盘为**死局**，必须自动洗牌（重新随机排列全部方块），显示提示文案"无可用步数，已重新洗牌"，且**不消耗步数**、不打断目标进度；
  4. 自动洗牌后必须再次保证至少 1 个合法交换（复用 FR-01 规则）。
- **异常处理**：洗牌后仍为死局（概率极低）必须再次洗牌，直至可玩。
- **验收要点**：AC-05、AC-06、AC-07。

#### FR-04 特殊方块（合成机制）及触发规则（高，SRC-A/SRC-B）

- **描述**：选题要求"消除/合成"。本作采用**消除为主、合成为辅**的解读：特定形状的消除即"合成"出特殊方块。三种特殊方块如下：

| 名称 | 合成条件 | 触发效果 |
| --- | --- | --- |
| 条纹方块 | 横/竖 4 连消除 | 被触发时清除整行（由横 4 连合成）或整列（由竖 4 连合成） |
| 炸弹方块 | T 形或 L 形 5 个消除 | 被触发时清除以自身为中心的 3×3 区域 |
| 彩虹方块 | 横/竖 5 连消除 | 与普通方块交换时清除全屏该颜色全部方块 |

- **规则**：
  1. 特殊方块在生成的那一轮**不立即触发**，保留在棋盘上等待后续交换触发；
  2. 触发条件：被包含在 3 连及以上消除中、被其他特殊方块效果波及、或（彩虹）与任意方块交换；
  3. **组合规则**：任意两个特殊方块相邻交换时，触发"组合爆发"——以交换位置为中心清除 3 行 + 3 列（十字形），并按 2 次连锁计分；彩虹与特殊方块交换按组合爆发处理；
  4. 被消除的特殊方块本身按普通方块计分（不额外加分）；其范围效果清除的方块正常计分并计入消除目标；
  5. 特殊方块必须在形状上与普通方块有明显区分（见 FR-19）。
- **异常处理**：特殊方块被锤子道具消除时正常消失，不触发范围效果（见 FR-09）。
- **验收要点**：AC-08、AC-09、AC-10。
- **设计说明**：纯合成玩法（如 2048 式两两合并）被否决——与本作三消框架冲突、学习成本与开发量显著增加，不符合"轻量"定位；否决理由详见《02_AI协作记录》。

#### FR-05 关卡目标、步数与过关/失败判定（高，SRC-A/SRC-B）

- **描述**：每关必须配置目标类型、目标值与步数上限；玩家在步数耗尽前达成目标即过关，否则失败。
- **规则**：
  1. **目标类型**（V1.0 仅两类，保证轻量与可验证）：
     - `score`：在步数内累计得分 ≥ 目标值；
     - `clear`：在步数内消除指定颜色方块 ≥ 目标数量（只统计通过消除/特殊方块效果消除的方块；锤子道具消除的方块**计入目标数量但不计分**）。
     （过关判定使用**局内累计得分/消除计数**，不含剩余步数奖励；剩余步数奖励仅在过关结算时计入总分并影响星级，见 FR-06-5、FR-07。）
  2. **步数**：每关 15–25 步（关卡配置）；仅有效交换消耗步数。
  3. **过关判定**：每次连锁结束时判定一次——若目标达成，立即进入过关结算（不等步数耗尽）；若步数已归零且目标未达成，进入失败结算。
  4. **目标显示**：局内界面必须实时显示"当前值 / 目标值"与"剩余步数"。
- **异常处理**：目标值必须 ≤ 该关配置下可达到的上限（关卡配置校验规则：见 7.1，发布前用自动求解器抽样验证可通关性，见 AC-11）。
- **验收要点**：AC-11、AC-12。

#### FR-06 计分规则（高，SRC-A/SRC-D）

- **描述**：积分是关卡过关与星级评定的基础，规则必须唯一且可复算。
- **规则**（唯一权威定义，其余章节不得另行定义）：
  1. 每个被消除方块基础分 20 分（含被范围效果清除的方块；特殊方块本身同价）；
  2. **连锁倍率**：第 n 次连锁（n≥1）的消除得分 × 倍率 B(n)，B(n) = min(1 + 0.5×(n−1), 2.5)。即：第 1 次 ×1.0，第 2 次 ×1.5，第 3 次 ×2.0，第 4 次及以后 ×2.5；
  3. 某次连锁得分 = 该次消除的方块总数 × 20 × B(n)；
  4. **剩余步数奖励**：过关时每剩余 1 步 +200 分；
  5. 结算总分 = Σ(各次连锁得分) + 剩余步数×200（仅过关时计算剩余步数奖励）。
- **异常处理**：锤子道具消除的方块不计分（见 FR-09），避免刷分漏洞。
- **验收要点**：AC-13（可复算性：测试人员按录像逐次连锁核对得分）。

### 5.2 成长与经济

#### FR-07 星级评定与过关奖励（中，SRC-B/SRC-D）

- **描述**：每关按结算总分评定 1–3 星，星级驱动收集动力与排行榜。
- **规则**：
  1. 星级比率 R = 结算总分 / 关卡目标分（`scoreTarget`，两类目标关卡通用；消除型关卡的目标分由关卡设计者配置，通常高于"刚好消除达标"的得分，用于拉开星级）；
  2. R ≥ 1.0 → 1 星；R ≥ 1.3 → 2 星；R ≥ 1.6 → 3 星；
  3. 失败结算 → 0 星，不得覆盖历史最好成绩；
  4. 过关奖励金币 +30；该关**首次**达成 3 星额外 +20；
  5. 重复挑战刷新个人纪录时，星级取历史最高并覆盖显示。
- **验收要点**：AC-14、AC-15。

#### FR-08 关卡结构与解锁（高，SRC-A）

- **描述**：关卡必须按章节线性组织并逐关解锁。
- **规则**：
  1. V1.0 共 3 章 × 10 关 = 30 关：第 1 章 7×7、4 色、20 步；第 2 章 8×8、5 色、18 步；第 3 章 8×8~9×9（逐关配置）、6 色、15 步（每关在章节基准上 ±3 步可配，字段约束见 7.1）；
  2. 解锁规则：第 1 章第 1 关默认解锁；通关某关解锁下一关；章内第 10 关通关后解锁下一章；
  3. 关卡选择页必须显示：每关星级（0–3）、锁定状态、章节总星数（x/30）；
  4. 已通关关卡必须可重复游玩。
- **验收要点**：AC-16、AC-17。

#### FR-09 金币与道具系统（中，SRC-B/SRC-E）

- **描述**：提供 3 种局内道具，用游戏内金币兑换；金币仅通过过关奖励获取（见 FR-07）。
- **规则**：

| 道具 | 效果 | 价格（金币） |
| --- | --- | --- |
| 洗牌 | 重新随机排列全部方块，不消耗步数 | 100 |
| 锤子 | 消除任意 1 个方块（计入消除目标数量，不计分，特殊方块不触发范围效果） | 150 |
| +5 步 | 本关剩余步数 +5 | 200 |

  1. 初始赠送每种道具各 1 个；持有上限每种 99 个；
  2. 道具在局内点击使用，**使用即消耗且生效**；若随后退出本局（刷新/关闭），已消耗道具不返还（与主流消除游戏一致，明确告知）；
  3. 失败结算界面若持有"+5 步"，应提供"使用道具续玩"入口（继续本局，步数 +5，棋盘状态保留）；
  4. 死局自动洗牌（FR-03）与道具洗牌效果相同但免费、不可主动触发。
- **异常处理**：持有数不足时道具按钮置灰，不得出现负数。
- **验收要点**：AC-18、AC-19。

#### FR-10 本地排行榜（中，SRC-A/SRC-E）

- **描述**：提供本机排行榜，满足"同宿舍/朋友间比分"诉求（画像 C）。
- **规则**：
  1. 两个榜单：**章节总星榜**（按总星数降序，同星按总分降序）与**单关最高分榜**（选关后查看该关本机历史最高 10 条）；
  2. 记录结构：{ 昵称, 关卡号或"全章节", 分数, 星数, 达成时间戳 }（见 7.3）；
  3. 昵称默认"玩家" + 4 位随机数字，可在设置中修改（长度 1–8 个汉字或字符）；
  4. **信任模型**：本作为单机游戏，排行榜数据存于本机且不作防篡改处理——这是"纯单机、无服务器"定位的显式代价，写入文档以消除歧义；
  5. 每条新纪录仅在高于该关历史第 10 名时入榜（保序淘汰）。
- **验收要点**：AC-20。

### 5.3 系统与界面

#### FR-11 存档与进度恢复（高，SRC-A/SRC-C）

- **描述**：游戏必须自动保存进度，刷新/关闭后进度连续。
- **规则**：
  1. 存档写入时机：过关/失败结算、章节解锁、金币与道具变动、昵称与设置变更、页面 `visibilitychange`/`beforeunload` 时；
  2. 存档内容 schema 见 7.2；**局内（进行中关卡）状态不存档**——刷新后回到该关初始状态，已用道具不返还（见 FR-09-2）；
  3. **损坏处理**：解析失败时，必须将损坏原文备份到独立键（`stardust_save_corrupt_<时间戳>`），重置为新档并在主界面提示"存档损坏，已重置"；
  4. **版本迁移**：`version` 字段不匹配时尝试迁移；无法迁移则备份 + 重置 + 提示；
  5. **写入失败**（隐私模式、配额耗尽）：必须显示横幅提示"进度无法保存，本局结果可能丢失"，游戏不因此崩溃；
  6. **存储不可用**（localStorage 被禁用）：允许单次会话游玩，提示"进度仅本次有效"；
  7. 首次进入游戏时提示："存档保存在本机浏览器，清除浏览器数据将导致进度丢失"（对应场景 SC-6）。
- **验收要点**：AC-21、AC-22、AC-23、AC-24。

#### FR-12 界面与页面导航（高，SRC-A/SRC-D）

- **描述**：提供 6 个页面：主菜单、关卡选择、游戏界面、结算界面、排行榜、设置。
- **规则**：
  1. 主菜单：开始游戏（有存档时显示"继续：第 x-y 关"）、排行榜、设置；
  2. 游戏界面：棋盘居中，顶部为关卡号/目标进度/剩余步数，底部为得分与 3 个道具按钮，右上角设置入口（局内只含音量开关与退出按钮）；
  3. 结算界面：过关 → 星级动画、结算总分、分享按钮（FR-17）、下一关/重玩；失败 → 重试、使用"+5 步"（条件显示）、返回选关；
  4. **响应式布局**：移动优先（竖屏），桌面浏览器棋盘居中、两侧留白；横屏移动设备不强制旋转，棋盘等比例缩放居中；
  5. 所有按钮触控目标 ≥44×44 px（移动端规范）。
- **验收要点**：AC-25。

#### FR-13 新手引导（中，SRC-D/SRC-E）

- **描述**：首次进入第 1-1 关时提供分步引导。
- **规则**：
  1. 引导 3 步：① 交换相邻方块（高亮一对可交换方块）；② 完成一次消除并说明计分与连锁；③ 说明目标进度条与步数；
  2. 总时长 ≤60 s，任意时刻可跳过；仅在首次进入时出现；
  3. 特殊方块首次合成时，以气泡提示其效果（每种一次）；
  4. 无引导时游戏必须依然可正常游玩（引导是可覆盖层，不阻断操作）。
- **验收要点**：AC-26。

#### FR-14 设置与数据管理（高，SRC-D）

- **描述**：设置页提供声音、昵称与数据管理。
- **规则**：
  1. 音乐开关 + 音量（0–100%）、音效开关 + 音量（0–100%），两项独立（默认均开启，音量 80%）；
  2. 昵称修改（FR-10-3）；
  3. **重置进度**：清空全部存档并恢复初始状态，必须二次确认，且须输入确认（弹出对话框点击"确认重置"），防止误触；
  4. 关于页：版本号、存档位置说明、隐私说明（无任何数据收集）。
- **验收要点**：AC-27。

#### FR-15 音效（高，SRC-A/SRC-C）

- **描述**：为关键事件提供音效与背景音乐。
- **规则**：

| 音效 | 触发事件 |
| --- | --- |
| 交换 | 有效交换 |
| 弹回 | 无效交换 |
| 消除 | 普通消除 |
| 特殊触发 | 条纹/炸弹/彩虹触发 |
| 连击 | 连锁 2 及以上（音高随连锁数升高，封顶连锁 4） |
| 过关/失败 | 结算界面出现 |
| 按钮 | 所有按钮点击 |

  1. 背景音乐为轻量循环（≤60 s 单循环，压缩后 ≤500 KB）；
  2. 音效采用 Web Audio API 合成或 ≤20 KB 短样本；加载失败或不支持 Web Audio API 时必须静默降级（无声音，游戏可玩，不弹错误）；
  3. 音效不得阻塞主线程，不得导致帧率下降（NFR-01）。
- **验收要点**：AC-28。

#### FR-16 动画反馈（高，SRC-A/SRC-D）

- **描述**：所有状态变化必须有动画反馈。
- **规则**：

| 动画 | 时长约束 |
| --- | --- |
| 交换/弹回 | ≤300 ms |
| 消除（缩放+粒子） | ≤250 ms |
| 下落+补充 | ≤300 ms |
| 特殊方块触发 | ≤400 ms |
| 星级结算动画 | ≤2 s，可点击跳过 |

  1. 动画必须与逻辑状态机严格同步（动画期间锁定输入，见 FR-02-3）；
  2. 动画必须为纯视觉反馈，不改变任何计分与判定结果；
  3. 支持系统"减少动态效果"偏好时，将消除动画缩短至 ≤150 ms（可选项，尽力而为）。
- **验收要点**：AC-29。

#### FR-17 成绩分享卡（低，SRC-E）

- **描述**：过关结算后提供成绩分享能力（本作唯一的"社交/分享"功能）。
- **规则**：
  1. 结算界面"分享成绩"按钮生成成绩卡：Canvas 绘制，尺寸 720×1280 PNG，含游戏名、关卡号、星级、总分、日期；
  2. 同时提供"复制文本"：固定格式 `我在《星尘消除》第 {章}-{关} 获得 {星级} 星 {总分} 分！`；
  3. 下载图片走浏览器下载能力，**不接入任何第三方社交 SDK**。
- **验收要点**：AC-30。
- **范围决策**：好友对战、好友排行榜、社交平台接入列入范围外（第 9 章），分享仅保留"成果展示"最小闭环。

#### FR-18 桌面键盘操作（低，SRC-D）

- **描述**：桌面浏览器支持键盘操作。
- **规则**：
  1. 方向键移动光标选中方块，空格/回车交换至箭头方向相邻格；Esc 返回上一页面/退出局内；
  2. 鼠标与键盘可随时混用，光标与鼠标悬停选中互不冲突。
- **验收要点**：AC-31。

#### FR-19 色觉友好显示（低，SRC-D）

- **描述**：方块采用"颜色 + 形状"双编码，避免红绿色盲玩家无法区分。
- **规则**：6 种颜色分别对应 6 种基础形状（圆形、方形、三角形、菱形、五边形、六边形），颜色与形状的映射在设置页可见图例。
- **验收要点**：AC-32（灰度截图下仍可按形状区分）。

## 7. 数据定义

### 7.1 关卡配置（JSON，每关一个对象，配置驱动）

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `id` | string | 是 | 唯一关卡号，格式 `{章}-{关}`，如 `2-5` |
| `chapter` | int | 是 | 章号 1–3 |
| `boardRows` / `boardCols` | int | 是 | 7–9（参考主流三消：开心消消乐为 7×7；棋盘格数为奇数不影响玩法，无需偶数约束） |
| `colors` | int | 是 | 4–6，方块颜色种数 |
| `objectiveType` | enum | 是 | `score` \| `clear` |
| `objectiveTarget` | int | 是 | 目标值；`clear` 型为消除目标色方块数 |
| `targetColor` | int\|null | 条件 | `clear` 型必填，指定目标颜色编号，且必须 ∈ 颜色池 |
| `moves` | int | 是 | 15–25 |
| `scoreTarget` | int | 是 | 星级基准分（见 FR-07）。`score` 型：等于 objectiveTarget；`clear` 型：独立配置的分数基准，须由关卡设计者验证可达 |

**配置校验规则**：加载关卡时必须校验上表约束，校验失败按 FR-05 异常处理（该关标记为配置错误并跳过，不得白屏）。发布前必须用自动求解器对每关抽样验证可通关性（AC-11）。

### 7.2 存档（localStorage 单键 `stardust_save`，JSON）

```json
{
  "version": 1,
  "nickname": "玩家1234",
  "unlockedLevelId": "1-3",
  "coins": 320,
  "items": { "shuffle": 2, "hammer": 1, "steps": 0 },
  "stars": { "1-1": 3, "1-2": 2 },
  "bestScores": { "1-1": 12400, "1-2": 9800 },
  "leaderboard": {
    "total": [ { "nickname": "玩家1234", "stars": 5, "score": 22200, "ts": 1710000000000 } ],
    "levels": { "1-1": [ { "nickname": "玩家1234", "score": 12400, "ts": 1710000000000 } ] }
  },
  "settings": { "musicOn": true, "musicVol": 80, "sfxOn": true, "sfxVol": 80 },
  "guided": true,
  "updatedAt": 1710000000000
}
```

| 约束 | 说明 |
| --- | --- |
| 单键体积 | 30 关全 3 星 + 每关 10 条榜记录 ≤50 KB，远低于 localStorage 约 5 MB 配额（SRC-C） |
| `version` | 结构变更时递增；不匹配走迁移/重置流程（FR-11-4） |
| 写入原子性 | 先写临时键再覆盖正式键；写入失败按 FR-11-5 处理 |

### 7.3 排行榜记录结构

- 总星榜条目：`{ nickname, stars, score, ts }`（stars 为全章节总星数，score 为全章节总分，均取本机最好成绩）；
- 单关榜条目：`{ nickname, score, ts }`（每关保留前 10 条，见 FR-10-5）。

### 7.4 分享文本格式

`我在《星尘消除》第 {章}-{关} 获得 {星级} 星 {总分} 分！`（示例：`我在《星尘消除》第 2-5 关获得 3 星 12800 分！`）

## 8. 验收标准

### 8.1 发布验收门槛（全部满足方可验收）

1. 30 关全部可通过自动求解器抽样验证可通关，且人工全通无阻塞性 Bug；
2. NFR-01 全部指标达标（性能）；
3. NFR-02 兼容矩阵通过；
4. 离线（断网）环境完整游玩 1 章无任何异常；
5. 无任何广告、内购、体力、账号登录相关代码与界面。

### 8.2 关键验收用例（AC）

| 编号 | 对应需求 | 前置 | 步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| AC-01 | FR-01 | 进入任意关卡 | 检查初始棋盘 | 无 3 连及以上；存在 ≥1 个合法交换 |
| AC-02 | FR-01 | 连续进入同关 100 次 | 统计开局死局次数 | 0 次 |
| AC-03 | FR-02 | 局内 | 交换形成 3 连 | 消除动画播放，步数 -1，得分按 FR-06 增加 |

## 9. 边界与范围外

### 9.1 范围包含（V1.0）

单机三消网页游戏；30 关（3 章）；3 种特殊方块；2 类关卡目标；计分/星级/金币/3 种道具；本地排行榜；自动存档；音效与背景音乐；新手引导；成绩分享卡（P3）；桌面键盘操作（P3）；色觉双编码（P3）。

### 9.2 范围外清单（每项均需理由）

| 范围外项 | 理由 | 潜在版本 |
| --- | --- | --- |
| 在线排行榜 / 云存档 / 账号系统 | 违背"纯单机、轻量"定位；需要服务器与账号体系，成本与隐私负担大 | V2.0（需重新评估隐私与成本） |
| 广告、内购、体力值 | 目标用户痛点来源（2.2），违背定位；课程项目无法运营变现 | 不考虑 |
| 好友对战、好友排行榜、社交平台 SDK 接入 | 超出"分享成绩"最小闭环，开发量不可控 | V2.0 |
| 纯合成玩法（2048 式） | 与三消框架冲突，学习成本与开发量双高（见《02_AI协作记录》否决记录） | 不考虑 |
| 障碍地形（冰块/锁链/传送门等） | 增加关卡配置复杂度与美术量，V1.0 以 2 类目标保证轻量 | V1.1 候选 |
| 计时/限时模式、每日挑战、无尽模式 | 制造时间压力或内容负担，与休闲定位冲突 | V1.1 候选 |
| 玩家关卡编辑器 | 开发量大，对目标用户无意义 | 不考虑 |
| 多语言（i18n） | 目标用户为中文玩家 | V2.0 |
| 原生 App / 微信小游戏封装 | 选题限定网页游戏 | V2.0 |
| 排行榜防作弊 | 单机信任模型（FR-10-4），防作弊无意义 | 与在线榜绑定评估 |
| 皮肤/主题装扮 | 装饰性功能，价值低 | V1.1 候选 |
